# Acceptance Criteria

## CRM Basics

- [ ] BOS Staff can create company, contact and deal records.
- [ ] Deal must belong to an event cycle.
- [ ] Deals board defaults to current active cycle.
- [ ] Deals can be viewed as board and list.
- [ ] Company and contact details open in side sheets.
- [ ] Deal details open in side sheet from board/list.

## Pipeline

- [ ] Deal can move through defined statuses.
- [ ] Approved participant status is available.
- [ ] Lost/cancelled require or allow reason.
- [ ] Approved participant deals can continue onboarding/provisioning work.

## Onboarding And Provisioning

- [ ] Deal sheet shows onboarding checklist progress.
- [ ] Checklist items can be completed inside deal sheet.
- [ ] Approved participant deal can create ToonExpo provisioning request.
- [ ] Repeated company participation uses new deal for new cycle.

## Boundaries

- [ ] BOS CRM does not show ToonExpo Constructor CRM as BOS deals.
- [ ] BOS CRM does not manage buyer requests or apartment sales.
- [ ] BOS CRM does not require full ToonExpo data sync in v1.
- [ ] Notes/attachments are stored on relevant entities, not a separate files module.

## Permissions

- [ ] BOS Viewer cannot edit CRM data.
- [ ] BOS Staff can work assigned/allowed deals.
- [ ] BOS Admin can manage all CRM records and settings.
- [ ] Important status/provisioning/checklist changes are auditable.
